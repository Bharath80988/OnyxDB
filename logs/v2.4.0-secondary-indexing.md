# OnyxDB v2.4.0 Release Log: Secondary B+ Tree Indexing

**Release Date:** July 28, 2026  
**Module:** `onyxdb-core` & `onyxdb-api`  

---

## Technical Summary
OnyxDB v2.4.0 introduces **Secondary B+ Tree Indexing**, eliminating full-table scans for non-primary key queries. Client applications can dynamically create indexes on any JSON attribute field (such as `email`, `username`, `status`, or `role`). The query execution engine automatically intercepts `select` queries matching indexed attributes and resolves them via secondary index lookup in $O(\log N)$ time.

---

## New Features & Enhancements

### 1. `SecondaryBTreeIndex.java`
- Manages secondary attribute mappings using concurrent thread-safe data structures (`ConcurrentSkipListSet`).
- Maps `SecondaryFieldValue (String)` $\rightarrow$ `List<PrimaryID (int)>`.
- Provides lookup, insertion, update, and removal methods.

### 2. Administrative Action: `create_index`
- Endpoint request schema:
  ```json
  {
    "action": "create_index",
    "table": "users",
    "field": "email"
  }
  ```
- Scans existing B+ Tree pages to index all pre-existing records on creation.
- Secured behind `ADMIN` Bearer authentication tokens.

### 3. Automated Secondary Index Maintenance
- **Inserts**: Automatically extracts registered fields and updates secondary indexes upon record insertion.
- **Updates**: Detects modified fields and updates secondary index mappings dynamically.
- **Deletes**: Purges secondary index pointers when records are deleted.

### 4. Index-Accelerated Query Routing
- When executing:
  ```json
  {
    "action": "select",
    "table": "users",
    "where": { "email": "satoshi@bitcoin.org" }
  }
  ```
- `ExecutionEngine` checks if `email` is indexed. If present, it executes a **Secondary Index Scan**, fetching matching primary key IDs and directly retrieving target records from primary B+ Tree pages.
