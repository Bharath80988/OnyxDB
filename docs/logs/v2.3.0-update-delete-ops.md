# v2.3.0 - Mutative & Destructive Operations with Binary Search Acceleration

## Overview
In version 2.3.0, OnyxDB added full support for B+ Tree `update` and `delete` operations, accelerated by a $O(\log N)$ binary search algorithm within node pages. The operations are fully integrated into Write-Ahead Logging (WAL) for 100% crash durability, protected by Role-Based Access Control (RBAC), and integrated into the REST API layer.

## Technical Architecture & Changes

### 1. B+ Tree Node Binary Search Algorithm (`BTreeManager.java`)
- **Binary Search Indexing**: Added `binarySearchLeaf(Page leafPage, int numRecords, int targetId)`. Replaced $O(N)$ sequential scanning with $O(\log N)$ binary search across the 256-byte record slots within 8KB leaf pages.
- **In-Place Update (`update`)**: Locates the record slot using binary search, clears previous record byte allocations, and writes updated data payload. Sets page dirty flag.
- **Record Slot Shift Deletion (`delete`)**: Locates target record index in leaf page. If records exist after the target, shifts them left by 256 bytes (`RECORD_SIZE`) via `System.arraycopy`, zeros out the trailing record slot, and decrements `numRecords`.

### 2. Write-Ahead Logging & Crash Recovery (`ExecutionEngine.java`)
- **Mutative WAL Persistence**:
  - `UPDATE` actions write `UPDATE:<id>:<value>` to table `.wal` files prior to modifying page memory.
  - `DELETE` actions write `DELETE:<id>` to table `.wal` files.
- **Crash Recovery Replay**: Modified table startup recovery loop to recognize `UPDATE:` and `DELETE:` prefixes, replaying updates and deletions to guarantee ACID durability upon engine restart.

### 3. REST API & Security Guard (`QueryController.java` & `QueryService.java`)
- **RBAC Role Enforcement**: Updated authorization layer to block `READ_ONLY` Bearer tokens from performing `insert`, `update`, or `delete` actions (returns `403 Forbidden`).
- **Spring Boot Cache Eviction**: Configured `QueryService` `@CacheEvict(value = "queries", allEntries = true)` for `executeMutative` operations to flush cached `SELECT` query results whenever data mutates.

## Testing & Verification
- Unit test suite `BTreeManagerTest.java` added covering `insert`, point `search`, `update`, `delete`, and `scanAll`.
